# 読者向けUIの設計判断

## 目的

読者が記事を選び、本文を読み、一覧や別の記事へ移動できることを優先する。
ブランド名・青緑の配色・ヒーロー・英語のナビゲーションは維持する。
説明の追加より、情報の順序と操作の明確さで補う。

## 参照した研究と実装

| 根拠 | このサイトでの判断 |
| --- | --- |
| Pirolli & Card (1999), *Information Foraging*, Psychological Review 106(4), 643–675. [著者提供の論文・抄録](https://www.researchgate.net/publication/229101074_Information_Foraging), [DOI](https://doi.org/10.1037/0033-295X.106.4.643) | 情報を得る価値と探索のコストを考える枠組み。ヒーローの高さを抑え、新着記事までの距離を短くする。 |
| Chi, Pirolli & Pitkow (2000), *The Scent of a Site*, CHI 2000. [論文PDF](https://scispace.com/pdf/the-scent-of-a-site-a-system-for-analyzing-and-predicting-2wgp630gsw.pdf) | リンク付近の文章などが行き先を判断する手掛かりになるという考えを適用。記事タイトルと要約を優先し、リンクは「すべての記事」「記事一覧に戻る」のように行き先を示す。 |
| W3C, [WCAG 2.2: Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) | 基準の24 CSS pxを参考に、分類リンクは高さ28px、ヘッダーの主要操作は44px以上にする。文中リンクには一律の最小寸法を課さない。 |
| W3C, [WCAG 2.2: Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html) | ユーザーによる文字間隔・行間変更を妨げない。1.5倍の行間などは上書き時の検証条件であり、デフォルト値の義務ではない。 |

これらは設計判断の根拠であり、本ブログでの効果を実験で証明したものではない。特定の行間・カードサイズ・ヒーローの高さが論文で最適と示されたわけではない。

## 情報と操作の優先順位

- 一覧：タイトル → 日付・分類 → 要約。要約は `description` を優先し、なければ本文の要約を使う。
- 本文：日付、分類、本文、見出しからの目次、記事末尾の移動先。著者紹介・読了時間・技術表記は繰り返さない。
- 記事タイトルと分類はそれぞれ独立したリンクにする。カード全面を覆うリンクは使わない。
- 一覧へのリンクにボタンを入れ子にせず、通常のリンク1つで表現する。
- 記事が1件でも記事末尾から一覧へ戻れる。記事が増えれば前後の記事名も表示する。
- 検索はPCで文字ラベルを添え、スマートフォンでは読み上げ名のあるアイコンを使う。

## 文字と幅

本文はコンパクトな行間1.3倍に統一する。行間の切り替えボタンや設定保存は設けない。この値は所有者の好みに合わせた調整であり、一般読者全員に最適な値とはしない。
記事選択に使う要約は別の変数 `--blog-summary-leading: 1.65` で管理し、本文の密度設定に巻き込まない。
サイトの横幅は最大1600px、本文は最大44remに制限する。

## 保守

変更は `assets/` と `layouts/partials/` に置き、テーマのサブモジュールは編集しない。
`article-link/simple.html` と `header/components/desktop-menu.html` はテーマのコピーを最小変更したもの。Blowfish更新時は元テンプレートとの差分を確認する。
検証用の記事は `/tmp/` の別コンテンツ・別出力に作成し、本番の記事一覧に混ぜない。

今後は実際の読者に記事探索と読書を試してもらい、迷う箇所や誤操作があった部分を修正する。アクセス計測は追加していない。

## 検証結果（2026-11-07）

Hugo Extended 0.169.0で本番用・検証用のビルドを確認した。
ヘッドレスChromeで以下を確認した。

- 320 / 390 / 768 / 1024 / 1440pxでホームに横はみ出しがない。
- PCの初期表示に最初の記事が入り、未表示の記事がある場合に一覧リンクが出る。
- 検索の起動と検索結果、モバイルメニューの開閉、目次の展開と見出しへの移動。
- スマートフォンのヘッダー主要操作が44px以上。
- 記事末尾に前後の記事と一覧へのリンクがある。
- 長いコードを含む記事と、行間1.5倍・字間0.12em・単語間0.16em・段落後2emへの上書きでページ全体に横はみ出しがない。
- ライト／ダーク両方のホーム、スマートフォンの長文記事を目視確認。

これはWCAG全項目への適合認証や、実読者によるユーザビリティ試験ではない。スクリーンリーダーでの操作確認、200%ズームでの全ページ確認、実端末のタッチ操作は未実施。

後続調整：行間切り替えボタンと保存スクリプトを削除し、本文の行間を1.3倍に統一した。

## ナビゲーションの再配置

ヘッダーは **Home / Posts / About** と外観切り替えに絞る。検索・カテゴリー・タグ一覧は `/posts/` の上部にまとめる。PCとスマートフォンで同じ構造を使う。

| 想定する読者の目的 | 導線 |
| --- | --- |
| 初めて来て、最近の記事を読みたい | ホーム → 新着記事 → 本文 |
| 特定の話題・過去の記事を探したい | Posts → 検索、Categories、Tags → 記事 |
| 検索エンジンやSNSから記事へ直接来た | 本文 → 分類リンク、前後の記事、記事一覧に戻る |
| 書き手について知りたい | About |

Katz & Byrne (2003), *Effects of Scent and Breadth on Use of Site-Specific Search on E-Commerce Web Sites*, TOCHI 10(3), 198–220. [著者提供の全文](https://www.researchgate.net/publication/220286180_Effects_of_scent_and_breadth_on_use_of_site-specific_search_on_e-commerce_Web_sites), [大学公開PDF](https://chil.rice.edu/research/pdf/KatzByrne03.pdf), [DOI](https://doi.org/10.1145/937549.937551)。

同論文の2研究では検索・閲覧行動に利用者やサイトによる差があり、検索が必ずしも速く正確ではなかった。メニューの広がりと行き先の手掛かりが閲覧行動に影響した。検索を提供するだけでナビゲーション設計の問題を補えるとはしない。

この結果と情報探索研究を踏まえ、本ブログでは「読む」ための主要移動先と「探す」ための補助機能を分けた。ただし論文はECサイトを対象とし、ブログの検索をヘッダーから外す効果を直接検証したものではない。ヘッダー項目が少ないほど常に良い、という一般化もしない。現状の記事数と所有者の希望に合わせた設計仮説であり、実読者での検証は未実施。

検索のキーボードショートカット（`/`、Ctrl/Cmd+K）は維持する。機能への唯一の導線にはせず、Postsに文字ラベル付きボタンを置く。カテゴリー・タグは記事ごとの分類リンクからもたどれる。ヘッダーの検索ボタン削除に伴い、先のPC検索ラベルの配置判断をこの構成で更新する。

`layouts/posts/list.html` と `header/components/mobile-menu.html` もテーマの最小変更コピーを使用するため、テーマ更新時に差分を確認する。

再配置後の検証：320〜1440pxでホームと記事一覧に横はみ出しがなく、ヘッダーから検索・分類が外れ、記事一覧に3つの探索手段が残ることを確認。検索結果、Escで閉じた後のボタンへのフォーカス復帰、スマホメニューの3項目、記事からの分類・一覧導線、記事ページでのCtrl+Kをブラウザで検証した。
